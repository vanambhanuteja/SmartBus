# Machine-learning methodology

**Goal:** predict bus occupancy (%) for a route, hour and weekday, then map it to a crowd category.

**Data – SYNTHETIC.** No real KSRTC occupancy data was available, and none is claimed. `prediction-service/app/generate_dataset.py` simulates 8 weeks × 7 days × 16 hours × 12 routes = 10,752 rows (`data_source = SYNTHETIC`): per-route base demand × morning/evening peak curve × weekday factor + Gaussian noise (seeded, reproducible). `recent_reports_avg` is a noisy copy of the previous hour, imitating passenger reports.

**Features:** route_id, hour, day_of_week, historical_occupancy (mean of the same route/day/hour in the *training* weeks), recent_reports_avg (backend supplies the mean of real PASSENGER reports from the last 2 h; falls back to history if none).

**Model:** `RandomForestRegressor(n_estimators=100, max_depth=12)` → occupancy %; category thresholds 0–30 Low, 31–60 Moderate, 61–85 High, 86–100 Overcrowded.

**Evaluation:** temporal split – weeks 0–5 train (8,064 rows), last 2 weeks test (2,688 rows). Results from the actual run (`prediction-service/models/metrics.json`):

| Metric | Value |
|---|---|
| MAE | 5.15 percentage points |
| R² | 0.90 |
| Category accuracy | 0.802 |
| Weighted precision / recall / F1 | 0.800 / 0.802 / 0.800 |

**Interpretation / honesty:** these numbers describe how well the model recovers a *simulated* pattern that was generated by simple rules. They are **not evidence of accuracy on real buses**. Confusion matrix errors are mostly adjacent categories (e.g. Low↔Moderate). To go real: collect `PASSENGER` reports, export them to the CSV schema, retrain with `python -m app.train`, re-evaluate.

**Reproduce:** `cd prediction-service && python -m app.generate_dataset && python -m app.train && pytest`.
